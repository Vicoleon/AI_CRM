# Cubie Phase 2 Workspaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. The original task checkboxes are implementation instructions, not a verified completion ledger; use the dated checkpoint below for evidence.

**Goal:** Run one Cubie service for isolated company workspaces, with repeatable local setup, dry-run-ready provisioning and deployment, and a workspace choice of client-owned AI model credentials.

**Architecture:** A separate control database maps verified identities and inbound integrations to workspaces. Each workspace owns a separate database, storage namespace, credentials and runtime state. An outer ASGI middleware and explicit job context select the workspace; database sessions bind to the selected engine per call.

**Tech Stack:** Python 3.10, FastAPI/Starlette, SQLAlchemy 2, Alembic, PostgreSQL/Cloud SQL, SQLite for local development and tests, React/TypeScript, Google Cloud Run, Secret Manager, GCS, Vertex RAG, Bash 3.2.

**Spec:** docs/superpowers/specs/2026-10-27-cubie-platform-design.md, §§4.3, 4.4, 5, 6 and 7. Binding rulings and code maps are in .superpowers/sdd/phase2-inputs/map2/; the file inventory below also makes the plan executable without those maps.

## Review Focus

Each case below is pinned by the named task's failing test.

1. Concurrent sessions for two workspaces must never bind to the other's engine (Task 1).
2. A stale token, unknown hosted domain, suspended workspace or support actor removed from platform admins must never route to another workspace (Tasks 5 and 7).
3. A Slack/Fathom payload or browser key claiming another workspace must fail before any workspace DB access (Tasks 10–12).
4. A stored GCS or local URI, or RAG file ID, owned by another workspace or escaping its namespace must be refused on read and delete (Task 17).
5. An incomplete freeze/control-DB check or a dry run without gcloud installed must stop safely and never perform a write or reveal a password (Tasks 18–19).
6. A selected client-owned model provider must use only that workspace's credential and allowed endpoint. Invalid, revoked, missing or cross-workspace keys must refuse the call without silently spending another workspace's key or Cubie's Vertex quota (Task 21).
